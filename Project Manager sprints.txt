● Excellent — l'auth est déjà bien structurée avec tokenVersion (parfait pour blacklist refresh) et HttpOnly  
  cookies. Pour minimiser le risque de régression, je vais procéder de manière non-disruptive :               
                                                                                                              
  Approche refresh tokens (additive, pas breaking) :                                                          
  1. Ajouter un cookie refresh_token séparé, 7 j, HttpOnly                                                    
  2. Le cookie auth_token actuel devient le access token (15 min en prod, configurable)                       
  3. Nouvelle route POST /api/auth/refresh : vérifie le refresh, émet un nouveau couple, rotation             
  4. Logout invalide le couple via tokenVersion++                                                             
  5. Login émet les deux tokens                                                                               
  6. Backward-compat : tokens existants continuent à fonctionner jusqu'à expiration naturelle
